# PepitoWallpapers

Wallpaper partner customization APK for the Palm PVG100 (pepito).

## Why this exists

LineageOS ships `ThemePicker` (`vendor/lineage/config/common_mobile.mk`), which
uses WallpaperPicker2's `DefaultCategoryProvider`. That provider builds its list
from five sources, and the largest one -- "system categories" -- comes from a
*partner customization APK*:

    DefaultCategoryProvider.getSystemCategories()
      -> DefaultPartnerProvider.findSystemApk()
           PackageManager.queryBroadcastReceivers(ACTION_PARTNER_CUSTOMIZATION)
           filtered to ApplicationInfo.FLAG_SYSTEM
      -> partnerRes.getIdentifier("wallpapers", "xml", packageName)

Neither Lineage nor the Mi8937 device tree provides one, so that call returned an
empty list and the picker offered only "My photos" plus the single built-in
`default_wallpaper`. This package fills that gap.

## Provenance of the images

The six photographic wallpapers are the ones that shipped on stock Palm 8.1
(`Palm/PVG100/Pepito:8.1.0/OPM1.171019.019/v1AML-0`). On stock they were not in a
partner APK -- Android 8 used the old Launcher3-era `WallpaperPicker` app, which
bundled them in its own resources. They were lifted verbatim from:

    system/app/WallpaperPicker/WallpaperPicker.apk
      res/drawable-nodpi-v4/{water,plant,heart,pink,gold,donut}.jpg

All six are 720x1280, i.e. exactly the FT8613 panel resolution -- no rescaling was
applied. The `*_small.jpg` thumbnails that sat alongside them were deliberately
*not* copied: WallpaperPicker2 generates its own thumbnails when the optional
`thumbnail` attribute is absent, so shipping them would waste ~300 KB.

## Solid colours

Generated by `tools/gen-solids.py` -- rerun it to change the palette.

They have to be real encoded bitmaps rather than XML `<shape>`/`<color>`
drawables, because `ResourceAsset.openInputStream()` pipes
`Resources.openRawResource()` into `BitmapFactory`/`BitmapRegionDecoder`; an XML
drawable decodes to null and the tile renders blank. A flat 720x1280 PNG costs
~4 KB, so the whole set is smaller than one photographic wallpaper.

## Gotchas if you edit res/xml/wallpapers.xml

- `title` and `src` are read with `getAttributeResourceValue()`, so they must be
  resource references (`@string/...`, `@drawable/...`). A literal string yields 0
  and the entry is silently dropped.
- `id` is the exception -- it is a plain string (`getAttributeValue()`).
- A `<category>` with no successfully-parsed wallpapers is discarded entirely.
- `res/values/bools.xml` sets `default_wallpapper_hidden` to true, which drops the
  built-in Lineage `default_wallpaper` from the "On-device wallpapers" category
  now that this package supplies its own. Note the upstream misspelling
  ("wallpapper") preserved in `PartnerProvider.RES_DEFAULT_WALLPAPER_HIDDEN` --
  correcting it would silently stop the lookup from matching. This affects the
  picker listing only, not the wallpaper the device boots with on a fresh /data.
